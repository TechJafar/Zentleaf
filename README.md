## 3. User flows

- **Landing → Discovery:** Home → Services/Industries overview → deep dive into a service/industry sub‑page → contact form or case study.
- **Talent flow:** Home → Careers → Job Search → Apply (external ATS).
- **Content consumption:** Home → Insights listing → Article → related content or CTA.

## 4. Page-by-page UI and layout

### Home page (top to bottom)

1. **Hero section**
   - Full‑viewport height, full‑bleed background image/video with dark overlay.
   - Centered headline (h1) in white, one line, large display weight.
   - Subheading (h2) below, smaller, white.
   - Primary CTA button: “Explore our work” or similar.
   - Bottom: scroll indicator (animated down arrow or thin line).

2. **Featured insights carousel**
   - Full‑width, light background.
   - Horizontal scrollable row of 3–4 cards (image + title + category + date).
   - Left/right arrow controls, dot indicators.

3. **Our capabilities** (Services overview)
   - Section heading: “What we do” (h2).
   - Grid of 5–6 service cards (icon + title + short description + link).
   - Two rows on desktop, single row on mobile.

4. **Industry expertise**
   - Alternating layout: text left / image right, then reversed.
   - 3–4 industry highlights. Each has an image, headline, body text, link to industry page.

5. **Client success stories** (Case studies)
   - Section heading: “Our impact” (h2).
   - Two large feature cards (image, client logo, quote, results, link).
   - Below: grid of 3 smaller case study cards (image, title, industry tag).

6. **Thought leadership** (Insights)

## 9. Responsive behavior

| Breakpoint          | Layout changes                                                                                                            |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| Desktop (≥1024px)   | Multi‑column grids (3‑col), horizontal carousel, sticky header with full nav, side‑by‑side hero.                          |
| Tablet (768–1023px) | Grids become 2‑col, carousel still horizontal, hamburger menu replaces full nav, hero reduced height.                     |
| Mobile (<768px)     | Single column, stacked cards, hamburger menu, hero full‑screen with smaller text, carousel becomes swipeable single card. |

**Typography scales down proportionally:** h1: 32px, h2: 24px, h3: 20px, body: 16px.  
**Spacing halved on mobile:** 16px padding becomes 8px.  
**Images remain full‑width, aspect ratio preserved.**

## 10. Accessibility

- **Keyboard navigation:** All interactive elements focusable, visible focus ring (2px solid red).
- **Skip to content link** at top.
- **Alt text** on all images.
- **Form labels** visible, not placeholder only.
- **Color contrast:** Text vs background meets WCAG AA (4.5:1). Red accent used only for decorative elements or links (not for critical info alone).
- **ARIA labels** on carousel, dropdown, search overlay.
- **Language attribute** set to `en`.

## 13. Edge states and quality bar

- **Loading:** Skeleton screens for carousels, article grids.
- **Empty:** “No results found” with suggestion to adjust filters.
- **Error:** 404 page with site logo, message, link to home.
- **Form errors:** Inline validation messages, red border on invalid fields.
- **Performance:** Lighthouse scores ≥ 90 for desktop, ≥ 80 for mobile.
- **Content quality:** All placeholder copy must be replaced with real content before launch. No lorem ipsum.

## 14. Acceptance criteria

1. **All listed pages** exist with correct URL paths and section order.
2. **Shared chrome** (header, footer) is identical on every page.
3. **Visual system** is consistent: same colors, typography, spacing, radii, shadows, icon style across all pages.
4. **Home page** has all sections (hero, carousel, capabilities, industries, case studies, thought leadership, careers callout).
5. **Responsive behavior** matches breakpoints: grid reflows, navigation collapses, typography scales.
6. **Interactions** work as described: sticky header, carousel, hover effects, dropdown menus, mobile menu.
7. **Accessibility** requirements met: keyboard navigation, focus ring, alt text, form labels.
8. **No redesign** – the clone looks and behaves like the original site, not a generic SaaS template.
9. **Content density** matches original: same number of cards, same whitespace, no extra sections.
10. **Form submission** works with validation and success/error states.

## Development & Operations

### Prerequisites
- Node.js >= 20.0.0 (Node 22+ recommended)
- npm >= 10.0.0

### Getting Started

```sh
# 1. Install dependencies
npm install

# 2. Start local development server (with HMR)
npm run dev

# 3. Typecheck codebase
npm run typecheck

# 4. Lint codebase
npm run lint

# 5. Build for production (SSR + static assets)
npm run build

# 6. Preview production build locally
npm run preview
```

### Architecture Overview
- **Framework**: TanStack Start (React 19 + SSR + Vite)
- **Routing**: TanStack Router (File-based routing under `src/routes/`)
- **Styling**: Tailwind CSS v4 with Radix UI headless components
- **State Management**: TanStack React Query for async caching and React hooks for local state
- **Server Deployment**: Nitro server entry (targets Cloudflare, Node.js, Vercel, or custom servers)
